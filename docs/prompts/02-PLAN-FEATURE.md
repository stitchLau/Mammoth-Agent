# Prompt 02 — 功能规格与实施计划

针对【填写功能/需求】开展工作。先不要修改代码。

阅读 Master Guide、相关 Feature Spec、领域模型、架构基线、相关 ADR、当前代码和测试。

按以下格式输出：
1. 目标用户与要解决的问题；
2. 本次目标和明确非目标；
3. 当前实现事实（带文件/符号/测试证据）；
4. 领域模型、状态、权限、数据影响；
5. 正常流程、异常流程和边界条件；
6. UI/API/Agent Tool 影响；
7. 实施步骤及拟修改文件；
8. 测试计划和可观察验收条件；
9. 安全、迁移、兼容和回滚风险；
10. 未知、假设、需要负责人决定的问题。

检查是否与完整产品边界冲突。若建议延期某项能力，标记为“实现延期”，并指向路线图/backlog，不得删除产品要求。

先产出 Feature Spec 和 Implementation Task 草案，待确认后再实施。
