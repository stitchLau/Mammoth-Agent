# S5 — Artifact Storage Spike（ADR-0004 证据）

- **版本**：0.1
- **日期**：2026-11-12
- **目标**：为 ADR-0004 提供证据——M1 原始资料（Artifact）不可变存储方案。
- **环境**：Windows 10 x64；JDK 17.0.15；Maven 3.9.11；SQLite 3.54（sqlite-jdbc 3.54.1.0）。
- **方法**：`spike/adr-0004-artifact/` 对 6 个合成文件（4 份唯一内容：小 Markdown、100 KB 随机、5 MB 随机、0 字节；2 份重复副本）分别执行两种存储，测量写入/读取/去重/只读/备份/删除恢复。输出 UTF-8 JSON（`target/result-*.json`）。

> 分类：**已验证**（实际运行并读到结果）/ **未验证**。一次性验证代码，不是产品基线。

## 1. 实测结果

| 指标 | A：本地内容寻址目录 | B：SQLite BLOB |
|---|---|---|
| 写入耗时 | **37 ms** | 296 ms |
| 读取耗时（读回+哈希校验） | **19 ms** | 43 ms |
| 逻辑数据量 | 10,589,776 B（约 10.1 MB） | 同左 |
| 实际占用 | **5,346,088 B**（去重后） | 5,365,760 B（DB 文件） |
| 去重 | 2 次跳过（同内容不同文件名只存 1 份） | 2 次跳过（`sha256 UNIQUE` + `INSERT OR IGNORE`） |
| 哈希校验 | ✅ 全部一致 | ✅ 全部一致 |
| 只读/不可变 | ✅ `dos:readonly` 生效；**删除被拒**（需先清除只读属性） | 行级删除是普通 SQL DELETE，**无文件级不可变保护** |
| 备份 | 目录复制 **6 ms / 5.35 MB** | `VACUUM INTO` **22 ms / 5.37 MB** |
| 删除→恢复 | ✅ 消失→从备份恢复 | ✅ 消失→从备份恢复 |
| 存储路径 | `<root>/artifacts/<sha[0:2]>/<sha[2:4]>/<sha>` | `artifact(sha256 UNIQUE, bytes BLOB)` |

## 2. 关键结论

1. **文件系统内容寻址在 M1 场景更合适**：写入快约 8 倍（37 vs 296 ms）、读取快约 2 倍、备份更快；且天然支持文件级只读不可变、备份就是普通目录复制、故障排查可用资源管理器直接查看。
2. **SQLite BLOB 不差但更耦合**：字节与元数据同库，备份/恢复简单（单文件），但 5 MB 级写入明显更慢、数据库体积随资料增长、WAL/checkpoint 与 DB 备份绑定；且删除保护需应用层额外实现。
3. **两方案都能满足去重与哈希校验**（sha256 作为唯一键）。
4. **0 字节文件**：两方案均正常工作。
5. Windows 只读属性可作为第一层防误删/防覆盖保护；但**删除操作必须显式清除只读属性**（本 Spike 验证了该保护实际生效）。

## 3. 建议（写入 ADR-0004）

- **M1 采用方案 A：本地内容寻址目录**，元数据（project_id、sha256、原始名、mime、size、上传人、时间）存 SQLite；二者通过 `sha256` 关联。
- 写入协议：临时文件 → `ATOMIC_MOVE` → 置只读；已存在同 sha 则跳过（去重）并记录复用。
- 读取时校验 sha256（成本低，实测 19 ms 含 10 MB 校验）；校验失败视为存储损坏，触发告警。
- 备份：数据目录树 + SQLite 库一起备份；恢复顺序先库后文件（或同快照窗口），并提供一致性校验脚本。
- 删除/清理：仅管理员授权流程可清除只读并删除；审计记录。
- **抽象接口 `ArtifactStore`**：`put/get/verify/exists/delete`；M1 实现本地内容寻址，服务端阶段可替换为对象存储（S3/MinIO，key = sha256）——**本轮未实现对象存储**。

## 4. 风险与未验证

| 项 | 说明 | 后续 |
|---|---|---|
| 对象存储未验证 | S3/MinIO 仅在 ADR 中作为服务端阶段候选 | 服务端阶段 Spike |
| Windows 长路径 | 内容寻址路径短（约 `<root>/artifacts/ab/cd/<64hex>`），避免了原始名导致的超长路径；但数据根目录本身不能过深 | M1 启动自检 |
| 杀毒/索引干扰 | 大量小文件可能被 Windows Defender 扫描影响性能 | 观察；必要时排除数据目录（需安全评审） |
| 并发写 | 同一 sha 并发写入需临时文件名唯一 + 原子移动；未做并发压力测试 | M1 T5 补测试 |
| 备份一致性 | 文件与 DB 非同事务；恢复需校验 sha | 备份脚本 + 校验脚本 |
| 大文件 | 5 MB 已验证；GB 级未测（流式哈希/写入需补充实现） | M1 T5 补流式路径 |
