# S7 — 检索/RAG Spike（ADR-0005 证据）

- **版本**：0.1
- **日期**：2026-11-12
- **目标**：为 ADR-0005 提供证据——M1 检索管线机制、排序策略、中文方案、权限过滤与引用结构。
- **环境**：Windows 10 x64；JDK 17.0.15；SQLite 3.54（sqlite-jdbc 3.54.1.0）。
- **方法**：`spike/adr-0005-retrieval/` 一次性探针。语料 12 篇合成中文知识文档（P1 8 篇、P2 4 篇，合计 12 个 chunk）；10 条查询（6 精确术语、3 部分措辞、2 语义改写），比较 fulltext / vector 基线 / hybrid。结果 UTF-8 JSON。

> 分类：**已验证**（实际运行）/ **未验证**（语义模型效果）。一次性验证代码，不是产品基线。

## 1. 实测结果

| 策略 | recall@1 | recall@3 | 平均查询耗时 |
|---|---|---|---|
| **fulltext**（FTS5 trigram + 查询三元组 OR + BM25） | **9/10** | **9/10** | 1,241 µs |
| vector（字符 trigram 哈希基线，256 维，余弦） | 6/10 | 9/10 | 623 µs |
| hybrid（RRF k=60） | 9/10 | 9/10 | 1,146 µs |

索引：12 chunks；构建 322 ms；索引 69,632 B；**重建 71 ms**，重建后 recall@3 不变（9/10）；**跨项目泄漏 0**（P1 查询未返回任何 P2 内容）。

唯一未命中：`库房盘货出现差异如何复盘`（期望 d3）——fulltext 无重叠 trigram 返回空，vector 基线排序错误；两条语义改写题中另一条（`不合格货物暂存位置和审批人`）fulltext 命中。

## 2. 关键发现

1. **FTS5 trigram 的整句查询必然 0 命中**：trigram 按"连续子串"匹配，自然语言问句不是文档的连续子串。首轮整句 MATCH 得到 0/10；改为"查询字符三元组 OR + BM25"后升到 9/10。中文无分词器场景下，这是可用的关键词兜底方案。
2. **hash 向量基线只反映字面重叠**，不是语义：recall@1 6/10（低于全文），语义改写题仍错排。因此**不能**用本轮结果推断"向量没用"或"向量有用"——需要真实 embedding 模型（本地或服务）才能评估语义检索。
3. **hybrid 在本基线无增益**（9/10，与全文相同）：因向量基线质量不足，RRF 只会引入噪声。混合检索应在真实 embedding 接入后再评估。
4. **权限过滤放在查询层**（`project_id` 条件）即可保证 0 泄漏；引用结构（doc/chunk/ordinal/text）可支撑"可核验引用"。
5. **索引可重建且便宜**（12 文档 71 ms），符合"索引是派生数据"的产品原则。

## 3. 建议（写入 ADR-0005）

- **M1 采用全文检索**：SQLite FTS5（trigram）+ 查询三元组 OR + BM25 + 项目 scope 过滤；chunk 元数据（doc/chunk/ordinal/start_offset）与引用结构入库。
- **抽象 `SearchAdapter`**：`index(doc)/search(query, scope, topK)/rebuild()`；全文实现先落地，向量实现后置。
- **向量/混合检索延后**：不在 M1 验收路径内；单独 Spike 评估（必须用真实中文 embedding，测召回与成本），通过后再以 RRF 接入。
- **chunk 参数**：M1 初始 chunk≈80 字符、overlap≈20（本 Spike 值），需在真实长文档上复验。
- **中文分词**：M1 不引入分词器；若全文召回不足，评估轻量中文分词（如 jieba 本地库）或 embedding。

## 4. 未验证 / 后续

| 项 | 说明 |
|---|---|
| 语义检索质量 | 未接真实 embedding；本地模型（如 bge-small-zh ONNX）或服务 API 需单独 Spike（离线、隐私、成本、体积） |
| 长文档切分 | 语料文档都很短（每篇 1 chunk）；长文档切分策略与召回需真实文档复验 |
| 关键词三元组方案的噪声 | 未测大规模语料下的误召与性能（当前 12 chunks） |
| 向量库选型 | 未评估（M1 暂不需要）；服务端阶段再定 |
| 引用定位精度 | 只到 chunk/ordinal；页码/行号/DDL 对象等精确定位在 M1 T8 落地 |
| 权限 | 只验证了 project scope；工作项/文档级权限在 M1 后续切片 |
