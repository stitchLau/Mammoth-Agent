# 01 — 产品章程（Product Charter）

## 1. 产品名称

Mammoth Agent

暂定英文副标题：Project Intelligence & Work Assistant。

## 2. 产品愿景

成为项目制企业中持续理解客户、产品、项目和工作历史的 AI 工作入口，使内部人员能够基于可靠上下文更快地理解项目、澄清工作、制定业务与技术方案、协调实施并沉淀组织经验。

## 3. 目标用户

- 产品经理/产品负责人：梳理产品能力、产品版本、需求优先级和产品经验。
- 项目经理/交付经理：理解项目状态、历史决策、范围、风险和交付资料。
- 业务分析/售后需求负责人：澄清客户问题，形成完整业务闭环方案。
- 软件开发/架构人员：理解项目代码、数据结构、接口、历史定制和变更影响。
- 测试/实施/运维人员：依据业务流程、异常路径和验收标准开展验证与现场工作。

## 4. 目标场景

首个领域从制造业软件项目切入，支持 MES、WMS、SRM、APS 等产品及客户项目；领域模型保持泛化，以便扩展到其他项目制企业。

## 5. 核心价值

1. 减少项目知识依赖个人记忆和即时问人。
2. 缩短新人员理解项目和历史需求的时间。
3. 提高需求澄清、方案编制和影响分析质量。
4. 让业务方案与技术方案保持一致并可追溯。
5. 让开发执行结果重新进入项目知识体系。
6. 将客户项目中的可复用经验沉淀为产品级或公司级知识。

## 6. 关键产品对象

组织、用户、客户、产品、产品版本、项目、项目版本基线、项目资料、知识文档、知识来源、工作项、需求证据、决策记录、方案版本、开发任务、执行记录、交付记录、Agent Run、审批记录。

## 7. 第一版成功标准

用一个真实但已获授权、完成脱敏的项目，完成一条端到端验证路径：

- 建立客户、产品和项目档案；
- 关联源码和项目资料；
- 对项目进行分阶段逆向并产出可追溯知识；
- 能按项目边界检索知识并回答问题；
- 创建一个从模糊描述开始的需求工作项；
- 持续补充材料，识别缺口与冲突；
- 生成业务方案、技术方案和开发任务；
- 导出交接包给外部 Coding Agent；
- 回收实际实施记录，比较偏差；
- 生成人工确认后的最终交付文档并更新知识。

第一版可以手动导入工单、手动交接给外部 Agent；不把 CSM/Jira API 集成作为端到端闭环的前置条件。

## 8. 非目标

- 第一版替代 CSM/Jira/ERP/MES 等正式业务系统。
- 第一版直接接管客户生产系统或自动提交高风险业务交易。
- 第一版自动调度所有外部 Coding Agent。
- 第一版实现完整企业级流程编排平台。
- 第一版建立复杂知识图谱或通用多模态训练平台。
- 第一版完成所有产品线的全面逆向。

## 9. 产品成功不是代码行数

应衡量：项目知识可用性、知识引用可追溯率、需求信息缺口识别有效性、方案审核质量、任务追溯完整度、实施偏差可见性、结项知识更新成功率、用户实际节省的工作时间。
