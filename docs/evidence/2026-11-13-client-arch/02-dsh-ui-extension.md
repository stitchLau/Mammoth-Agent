- **日期**：2026-11-13
- **研究目标**：为 Mammoth Agent 客户端架构决策提供 DeepSeek Harness（DSH）客户端 UI 扩展能力的**事实级**证据：插件模型、Slot 体系、自定义 Chat 节点/业务卡片、Bundle 组成、主题/本地化、Desktop 差异、上游升级影响。
- **目标版本**：`@deepseek-ai/dsh` **0.2.2-rc.2**，Profile=`desktop`（Electron 桌面应用）。
- **只读边界**：未写入/安装/启用/卸载任何插件，未修改 Profile 与 `~/.dsh`；除本报告外未写工作区文件；未调用 `plugin_manager` 变更动作。
- **证据分级**：`[已确认]`＝有安装版源码/文档路径:行号或官方生成物直接支持；`[需实测]`＝契约存在但本机未做运行时验证；`[未知]`＝无证据，不作推断。

## 0. 结论摘要（先读这一段）

1. **客户端插件模型是稳定的公开契约，但只覆盖“Web 页面内的 Cordis/React 插件”**：`package.json.dsh.client`（`platform`/`inject`/`immediately`/`external`）+ `exports["./client"]` + lazy-CJS factory（`window.__ModuleLoader__.load({id, factory(require)})`），React 由浏览器静态模块表提供。[已确认]
2. **本安装版共 114 个 Client Slot**（由 `slot-catalog.ts` 全量枚举，见附录 A），覆盖：主内容区整页（`main` keyed）、左侧栏顶级导航（`sidebar.panellist` list）、右侧栏/底部/overlay、会话头部与 composer、Chat 行、工具卡片、设置页、插件管理页、ContextMenu、Toast 等。[已确认]
3. **“新增顶级导航目标 + 长期停留的业务页面”可行且有官方范例**：`ui-plugin-manager` 同时注册 `main`（key=`plugins`）+`sidebar.panellist`（id=`plugins`），并用 `ctx.layout.selectPanel(id)` 导航（`dsh-client-ui-plugin-manager/src/client/index.ts:82-86,129-173`）。这是 Mammoth 工作台页面的直接模板。[已确认]
4. **自定义 Chat 行/业务卡片可行**：`ConversationNodeDefinition` + `conversation.chat.node`（key = 自定义 `kind`）是官方推荐路径（`practices.md:37`、`docs/architecture.zh.md`「添加 Web Client Chat 节点」映射）。但**不能新增 Session 事件类型**（`practices.md:21`），数据必须来自既有事件、工具结果、Host 会话投影（`wire.view`）或已生成的 Remote。[已确认]
5. **一个 bundle 可以同时携带 Host 插件 + Client UI 插件 + MCP server 配置 + agent preset**：`dsh.bundle.patch` 支持有序多个 patch 文件（`publish.md:64`、`dsh-web-app/package.json:49-59`），官方 voice-input bundle 就是 Host+Client 同包示例。[已确认]
6. **最大约束：Mammoth 的领域数据进入 UI 的“第三方通道”不完整**。客户端插件可读的标准数据源是 Slot 标准 hooks（sessions/workspaces/projections）、已生成的 `ctx.remote.<namespace>`、`ctx.resources`；但**第三方包自行新增 Typert Remote namespace 需要仓库内的生成器产物**（`dsh-typert-loader` 只装载已生成的 `./typert`，生成器不在安装包内），因此 Mammoth 需要走「会话投影 wire.view / 既有 Remote（命令）/ 工具结果 /（需实测）host-webserver 自定义路由」组合。[已确认 + 需实测]
7. **最大风险：上游 Client/slot 契约没有 LTS 级稳定性承诺，且实际在 rc 期间变更**：0.2.1-rc.2 重命名 `ctx.menus→ctx.contextMenus` 并迁移 slot 归属、0.2.1-rc.4 改 reasoning body slot 字段、0.2.2-alpha.2 重命名导出类型、0.2.2-rc.1 要求自定义 overlay 显式声明窗口拖拽区（`docs/upgrade-guide/v*/`）。且 installer 的 `engines.dsh` 只做版本闸门，不保证 API 兼容。[已确认]

**一句话结论**：Mammoth **可以**以 DSH Bundle 形式获得一套“嵌入 DSH 工作台、覆盖会话内卡片 + 侧栏顶级页面 + 右侧面板 + 设置页”的业务 UI；但**不能**获得与 DSH 壳解耦的“独立应用级完整业务 UI”（无路由/应用壳替换能力、无 UI 组件库导入、iframe 被官方实践禁止），且需承担 rc 期 Client 契约变更与数据通道自建的最大风险。

## 2. Q1 客户端插件模型

### 2.1 打包契约：`package.json.dsh.client`

`[@deepseek-ai/dsh-package-manifest/src/types.ts:86-99]` 定义 `DshClientManifest`：

| 字段 | 语义（官方 JSDoc 原文要点） | 稳定性判断 |
|---|---|---|
| `platform` | “Client platform identifier; the Web consumer selects `web`.” | 公开契约；**本版只接受 `web`**（见 2.2） |
| `inject` | 包名依赖（信息性），**不是 Cordis service 注入**；用于保证动态提供者先于消费者加载 | 公开契约 |
| `immediately` | 启动 phase-one 注册屏障；缺省表示进入共享 application batch | 公开契约 |
| `external` | 静态模块表之外的**精确**模块请求（含子路径如 `<pkg>/client`）；纯类型 import 被擦除 | 公开契约（但 practices 明确不建议借此绕包边界） |
| `exports["./client"]` | 浏览器 bundle 出口 | 公开契约 |

Bundle 侧另有 `dsh.bundle`（`types.ts:70-78`：`platforms?`、`patch: string|string[]`、`listedByDefault?`）与 `engines`（`types.ts:58-68`：`dsh`/`node`/`npm`）。[已确认]

模板最小示例：`templates/decoration/package.json:13-20`：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "immediately": true, "inject": ["@deepseek-ai/dsh-client-ui-conversation"] }
}
```

### 2.2 加载链（Host 侧扫描 → boot graph → 浏览器 lazy-CJS）

1. **识别**：Host 半 `dsh-client-modules` 扫描 Host Loader 中声明 `dsh.client` 的包，并读取其 `exports["./client"]`（`docs/subsystems/client-modules.md:94`）。
2. **平台闸门**：`dsh-client-modules/src/index.ts:905`：`if (decl === undefined || decl.platform !== 'web') return null` —— **本版 Web 客户端只消费 `platform: 'web'`**，desktop profile 复用同一套 web bundle（见 §7）。[已确认]
3. **组成 boot graph**：`window.__DSH_BOOT__` 的 `WebBootGraph`，元素为 `WebBootEntry { id, url, rev, inject?, immediately?, external? }`（`docs/subsystems/client-modules.md:11-38`）；`immediately` 决定是否 stage-one 预取（`:88`）。
4. **传输**：Web carrier 用 `/plugins` combo 路由；shell-owned carrier 用 `fetchBundle()` 返回同样内容（`dsh-client-modules/README.md:12`）。Desktop 属于后者（§7）。
5. **浏览器执行**：模块系统是 **lazy CommonJS 表**：执行 bundle 只注册 factory，module body 副作用（含 CSS 注入）在 materialize 时运行（`dsh-client-modules/README.md:12,43`；`client-modules.md:24`）。渲染前置条件是**完整 roster settle + boot audit 通过**（`web-client.md:26`；renderer README:94-95）。
6. **React 来源**：静态模块表（shell seed）提供 `react`/`react-dom`/`cordis`/`ui-slots` 等身份；业务 bundle 通过 `require('react')` 取用，禁止重复安装/CDN/UMD（`ui-plugin.md:9`；`dsh-client-ui-renderer/README.md:58`）。[已确认]
7. **类型/TS 构建**：官方客户端 bundle 由仓库内 `tsdown.client.ts` 预设产出；安装包内没有该构建器。第三方可手写等价产物（模板 `client.js` 即手写格式）。[已确认] 构建工具链不随运行时发布 [已确认-源码不可见]。

### 2.3 构建产物格式（必须精确匹配）

`templates/decoration/client.js:1-22`：

```js
window.__ModuleLoader__.load({
  id: '@local/my-decoration',
  factory(require) {
    const React = require('react');
    ...
    return { inject: ['slots'], apply(ctx) { ctx.slots.inject(...); } };
  },
});
```

要点 [已确认]：
- 只做“注册 factory”，不得有模块级副作用；资源/监听/CSS 必须在 `apply` 内用 `ctx.effect`/`ctx.on` 注册并返回 dispose（`ui-plugin.md:13`；`practices.md:8`）。
- `id` 必须等于包名（`ui-plugin.md:9`）。
- bundle 自己声明的非基线运行时 import 必须写进 `dsh.client.external`，否则组合期报错（`client-modules/README.md:55`）。
- 不能 `import` 任意模块；`require()` 只解析平台种子表、已声明 external、已注册 factory（`client-modules/README.md:77`）。
- 追加 chunk 走编译产物 `require.async`（`README.md:43,77`），第三方若要 code-split 需复刻该协议。

## 3. Q2 Slot 体系（0.2.2-rc.2 全景）

### 3.1 机制

- Slot 是 Web Client 的**类型化 React 组合系统**：`dsh-client-ui-slots` 定义 React-free registry 与类型代数，`dsh-client-ui-renderer` 把 observable 绑定成 hooks 并渲染（`slots.md:5`）。
- **声明（declare）**：包在 `SlotMap` 做声明合并（key/cardinality/scope/owner props/keyed props/可选 inject face）；运行时声明是拥有该渲染位置的组件的 `children` 条目。一个 live entry 独享一个声明；向未声明 slot 注册会在**插件激活时失败**（`slots.md:21-27`）。
- **注册（register）**：`ctx.slots.inject(ownerKey, () => ctx.slots.register(options, Component))`；owner collapse 时注册被移除，owner 重新挂载时 callback 重跑（`slots.md:27`；`practices.md:36`；`ui-plugin.md:11`）。
- **cardinality**（`slots.md:56-69`）：`single`（一个 cell，priority 胜者）/`list`（必填 id + order）/`keyed`（owner 派发 entryKey）/`chain`（select 选举，matched 传入）/`hoc`（包裹 children）。
- **scope**（同上）：`root` / `session-maybe` / `session`。
- **priority**：数值越小越先；普通增量贡献使用新 id/key，复用 shipped cell = 有意替换（`slots.md:69`）。
- **组件输入**（`slots.md:87-101`）：owner props、`PropsRenderSlots`、registration `store`、registration `inject` factory、locale `t`、chain `matched`、hoc `children`。组件**永远拿不到 `ctx`**。
- **框架标准 hooks**（`slots.md:103-121`）：`useSessions/useSessionStatus/useSessionRetainInfo/useSessionAccess`、`useWorkspaces/useWorkspaceAccess`、`useRemoteAccess`、`usePanelInfo`、session 的 `sessionId/useSession/useProjection/useAccess`、`useConversation/useInput/inputActions`、`useChat`、`useTrajectory`。
- **catalog 使用规则**（`slot-catalog.ts:72-79`）关键原文：不能传 `priority`（浏览器 half facade 自动分配且低于所有 shipped entry，因此在 single/keyed 中**你的条目会渲染**）；不能 `import` 设计系统组件，只能 `React.createElement` + `styles.insert(css)`；主题必须用 `var(--dsw-alias-*)`；catalog 是编译期契约，key 只有其 owner 挂载时才可注册。

### 3.3 重点确认项（逐条）

#### A. 应用级导航/侧栏入口 → **支持** [已确认]

- `sidebar.panellist` 是 **root-scoped list**，文档原文：`“Global panel icons. Each list id addresses the matching main panel; the sidebar owns the button and resolves its label from list metadata.”`（`slot-catalog.ts:4320-4372`）。
- ui-sidebar README 原文：`Plugins add an icon component to the root-scoped sidebar.panellist list with an id, optional order, and a string or locale-aware label. The same id addresses the component registered in the layout's root-scoped main keyed slot; selecting a missing main entry throws without changing the current selection.`（`dsh-client-ui-sidebar/README.md:42`）。另有 `More` 菜单（`sidebar.panellist.actions`）与 pin 语义（`README.md:44`）。
- 导航 API：`ctx.layout.selectPanel(id)`；`main` 的 `conversation` 是保留 key，`null` 表示回到 Conversation 且不改变当前 Session（`dsh-client-ui-layout/README.md:36`）；`selectPanel` 会先检查 live `main` registry，不存在则抛错并保持原选择（`README.md:63`）。

#### B. 全页面/主内容区业务页面 → **支持** [已确认]

- `main`：`kind: keyed, scope: root`，`keyDomain: open: any string the owner dispatches (no compile-time key set), already taken: conversation`；`declaredBy: an entry in 'root' (client-ui-layout)`（`slot-catalog.ts:2667-2706`）。
- 文档原文：`Other keys receive no Session binding.`（`slot-catalog.ts:2671`）——业务页面是**非会话绑定**的全局页面，但可用 `useSessions/useWorkspaces` 等 root 标准 hooks。
- **官方范例（直接可抄）** `dsh-client-ui-plugin-manager/src/client/index.ts`：
  - `PANEL_ID = 'plugins' as MainPanelId`（`:82-83`）

## 4. Q3 自定义 Chat Node 与业务卡片

### 4.1 机制：Conversation Definition + target + kind

- `ConversationNodeDefinition`（`dsh-client-ui-conversation/src/client/contract/conversation.ts:213-273`）字段：
  - `kind`：唯一渲染 kind；
  - `target?`：该 Definition 独占的 view target（省略=纯 state Context）；
  - `match(event)`：从**已有 Session 事件**提取稳定业务身份（`start`/`update`，可 `exclusive` 认领）；
  - `start/update`：状态机纯函数；
  - `buildViewNode(context)`：产生最终 Node（`key/kind/id/target/data`，`:140-146`）；
  - `buildLocationData?/publication?`：Turn/Step 级业务数据。
- 注册入口：`ctx.uiConversation.events.register(definition)`（`event-registry.ts:24-32`）；`match` 可写成“事件类型表”（`:74-83`）。Conversation Definition 可注册到已有 target（如 `chat`）或自行注册 target（`uiConversation.views.register`，`view-registry.ts:17`）。
- Chat target 侧：`conversation.chat.node` 以 `node.kind` 派发渲染器；`ChatNodeDataMap` 是**可声明合并**的 payload 表，`ChatNodeKind = Extract<keyof ChatNodeDataMap, string>`（`dsh-client-ui-chat/src/client/contract/chat-nodes.ts:23-35`）。插件在自己的类型里 declaration-merge 增加 kind/payload 即可获得类型安全。

### 4.2 能否渲染 Mammoth 领域对象卡片？→ **能，但数据必须“搭车”**

**不能做的事** [已确认]：
- **不能追加新 type 的 Session 事件**：官方 practices 原文：`Do not append session events with a new type. Readers accept an unknown stored event only when its envelope carries ignorable: true, and live Session.append() cannot set that marker, so the Session would refuse to reopen. appendPluginRecord() writes ignorable plugin: records, but it is reserved for DSH's experimental packages...`（`dsh-doc/references/practices.md:21`）。因此“自己定义领域事件类型并靠它渲染卡片”的路线对第三方 bundle **不可行**。
- 不能绕过 Runtime 直接伪造 tool-call 状态：工具卡片只接收 Runtime 权威的 phase 数据（`dsh-client-ui-tool/README.md:12`）。

**可行的三类数据路径**：

| 路径 | 说明 | 证据 | Mammoth 适用性 |
|---|---|---|---|
| A. 工具结果卡片 | Mammoth Host 插件注册工具（如 `mammoth_requirement_open` 等），client 插件按 wire tool name 注册 `tool.call.toolview` 卡片，从 `block.args/result` 渲染领域卡片，并可调用 UI 动作 | `dsh-client-ui-tool/README.md:38-56`；`slot-catalog.ts:5558-5676` | 高：最小成本，语义清晰；限制是卡片只在工具调用行出现 |
| B. 自定义 Chat 行 | Definition 匹配既有事件（常用：自己工具的 `tool/call`+`tool/result`，或 `assistant/message` 等）→ `buildViewNode` 返回自定义 `kind` → 注册 `conversation.chat.node` 渲染器；引擎负责分页/Turn/Step 定位 | `conversation.ts:213-273`；`practices.md:37`；`event-registry.ts:24` | 高：可做“需求卡/方案卡/交付卡”独立行，但必须在既有事件上提取 identity |
| C. Host 会话投影 + 渲染 | Host 插件贡献 `ProjectionDefinition`，声明 `wire.view` 把状态投影给客户端；客户端用 `useProjection`/标准 hooks 读取，再用任意 slot 渲染 | `dsh-session-projection/README.md:32-36,54-64`；`src/index.ts:105-110`；`practices.md:38`；`slots.md:113` | 高：适合“当前会话的 Mammoth 上下文摘要/进度/待办”，但不产生独立 Chat 行 |

另：`present` 工具的行由 `client-ui-deliverables` 占用（`slot-catalog.ts:5610`），`propose_action` 由 `client-ui-action-cards` 占用（`:5667`）——说明“业务对象卡片”在官方实现里也是通过 keyed toolview 扩展的，Mammoth 走同一模式合理。

### 4.3 与 Host 事件/工具结果的关联

- **工具结果**：卡片 owner props 的 `block` 即 Runtime 权威数据；`StartedToolCall`/`ToolResultNode` 含 args/result 与 PTC `subCalls`（`slot-catalog.ts:5573-5581`；`ui-tool/README.md:78-80`）。
- **Host 侧状态**：`ProjectionDefinition.apply(state, event)` 从已提交 Session 事件折叠，`wire.view` 输出客户端视图（`dsh-session-projection/README.md:54`）；`useProjection` 是 ui-session 提供的 session 标准 hook（`slots.md:113`）。
- **动作回传**：官方 user-actions 指引：UI 动作通过“Client-callable Host entry point”调用同一 Host 服务，例如 session command 经 `ctx.remote.commands.execute()`（`references/user-actions.md:8`）；Host 命令注册是公开 seam（`docs/architecture.zh.md` “添加用户命令 → 在 ctx.commands 上注册”；`packages.md:300`）。

### 4.4 业务卡片（Answer 下方）——`dsh-action-cards`（experimental）

- `dsh-action-cards` 属 **experimental** 组（`references/packages.md:196`：“Optional action cards below answers: one shared proposal tool, card state, user actions and status notices”）；`dsh-client-ui-action-cards` 提供卡片框 + body registry + `propose_action` 工具行（`packages.md:197`；`dsh-client-ui-action-cards/README.md:28-32,42-44`）。
- 机制：`ctx.actionCards.register({ action, locale, Body })`；一个 `conversation.chat.turnTail` entry 在 Turn 结束后展示卡片；`tool.call.toolview` keyed `propose_action` 渲染进程行（`README.md:32,42,44`）。
- 一致性规则：每 Turn 最多一张卡；同一 action 重复注册是错误（`README.md:32,78-79`）。
- 判断：**技术上可复用为 Mammoth“方案/交付确认卡”**，但该能力在 experimental 组（“Packages under experimental are pre-stable”，`packages.md:5`），且与 `personalized-recommendations` 的 Host 服务同装（`README.md:28`）。用于产品需独立 Spike 评估。[需实测]

### 4.5 限制清单（Chat/卡片相关）

1. 新事件类型不可用（§4.2）。[已确认]
2. 渲染 kind 由 `ChatNodeKind` 类型 + owner dispatch 决定；运行时注册一个 owner 不派发的 kind 不会渲染（catalog：`a kind with no occupant renders no row`，`slot-catalog.ts:502`）。[已确认]
3. 同一 key 的注册会**替换** shipped 渲染器（`replaceRisk: shadows-shipped-ui`），覆盖已占用 kind 需自负升级风险。[已确认]
4. 大列表/懒加载：Conversation 由引擎负责分页与增量组装，插件不得自行订阅 `session/event` 重扫（`practices.md:9,26`）；渲染应使用 slot props 的 selector hooks。[已确认]
5. 崩溃隔离：slot entry 崩溃会 blank 该 entry 并打印 `slot entry crashed in '<slot>'`（`practices.md:35`；`slot-catalog.ts:78`）。[已确认]

### 5.2 patch 方言（Loader）

`references/composition-reference.md:7-18`：
- `insert: [rows]` 追加；带 `id` 指向既有 `group: true` 行时插入其 `config` 列表。
- 带 `id` 无 `insert` = 覆盖既有行；**`config` 整体替换、不做深合并**，必须重述所有字段。
- 行字段：`id`、`name`（包 specifier）、`config`、`disabled`、`inject`、`intercept`、`isolate`；`group: true` + `name: cordis:group` 构成嵌套列表；`cordis:include` 从 `config.path` 载入列表。
- `!!js` 表达式在行注入激活后求值（`config` 内），`disabled` 支持 bool/null/`!!js`。
- 覆盖 shipped 行时用 `disabled: false` 打开官方禁用的行（`references/plugin-development.md:13`）。

### 5.3 安装 / 选择 / 升级 / 卸载流程

### 5.4 `engines.dsh` 兼容性机制

- 声明：`"engines": { "dsh": ">=0.2.0 <0.3.0" }`；安装与 profile 启动都会拒绝不满足的 bundle；**未声明 `engines.dsh` 时回退检查 `@deepseek-ai/dsh*` peer ranges**（`publish.md:66`；`dsh-package-manifest/src/types.ts:58-68`）。
- 优先级规则：`engines.dsh` 单独决定结果（不再被 DSH peer 放宽/收窄），只有缺 `engines.dsh` 才用 peer 规则（`docs/upgrade-guide/v0.2.1-alpha.3/plugin-engines-dsh/guide.md:12-21`）。
- 拒绝记录：`incompatible-version` + `requirements`（键为 `engines.dsh` 或 peer 包名）；豁免需 `compatibility.json` 精确 `package@version`→runtime 版本 + `acceptRisk`（`plugin-manager/README.md:77-83`）。
- **重要**：`engines.dsh` 只是**版本闸门**，不证明 API 兼容；跨 API 兼容仍需读 upgrade-guide 并重建 bundle。[已确认]

### 5.5 为什么外部 bundle 要“自带精确版本 @deepseek-ai 依赖”

- 官方规则原文：`Declare dsh packages whose instances the plugin must share with the host under both peerDependencies and devDependencies, as the harness packages do. At that manifest's lookup position, peers present in the running dsh's runtime resolution use the installation's copy; the devDependency copy serves your type checker and standalone tests.`（`publish.md:105`）
- 即：**Host 半**需要与宿主共享 Cordis service/事件实例 → 必须 `peerDependencies`（版本范围要覆盖可运行的 DSH 版本），dev 副本仅供编译/测试；运行时会用安装副本。第三方若还拆分出自己的包，独立版本依赖放 `dependencies`。
- 官方 bundle 的写法是**逐项精确版本**：`dsh-web-app/package.json:60-65`（全部 `0.2.2-rc.2`）、`dsh-experimental-voice-input-bundle/package.json:39-44`（全部 `0.2.2-rc.2`）、`dsh-desktop-host/package.json:13-35`。
- **Client 半**的额外规则：不要运行时 import 任何 Harness Client 包（`practices.md:35`），React 等基线从模块表取；因此 client bundle 通常**没有** `@deepseek-ai` 运行时依赖，只有 Host 半需要共享实例的依赖。定位为“类型共享 + 单实例保证”，而不是“客户端库依赖”。[已确认]

### 5.6 组合/分发限制

- bundle 只能“叠加配置层”，不能替代 profile 或修改他人 profile；管理自己的 management 组件不可禁用（`plugin-manager/README.md:179`）。
- 每个 bundle 有 Plugin Manager 列表项与详情页（`meta.title/description`、icon、`meta.detail` 可选单图文档）；`files` 必须包含 patch/locale/文档/图标与所有运行文件（`references/host-plugin.md:29-56`；`references/plugin-details.md:3-21`）。
- `official`/`optional`/`on-demand` 列表编译进安装（`dsh-official-bundles/README.md:31-44,82`）：第三方 Mammoth bundle 不能成为“安装版可选 bundle”，只能作为 profile 安装的外部 bundle（或私有分发）。
- preset 只能在 bundle patch 中声明/覆盖，Plugin Manager 不能编辑 preset 组成（`dsh-plugin-manager/README.md:179`；`compositions.md:69`）。

## 6. Q5 主题 / 本地化 / 样式

### 6.1 主题 token

- 样式必须用 `--dsw-alias-*` 等主题 token；官方原文：`Style with the theme tokens (--dsw-alias-*) ... literal colors are for artwork only. A renamed token degrades appearance but never breaks rendering.`（`practices.md:34`）。catalog 规则：`Use the theme CSS variables (var(--dsw-alias-bg-layer-1), var(--dsw-alias-label-primary), …) instead of literal colors, or your contribution breaks in the other color scheme.`（`slot-catalog.ts:76`）。
- token 来源：`dsh-client-ui-theme` 提供 `--dsw-*` stylesheet；`ctx.theme` 暴露快照；第三方主题可通过 `ctx.theme.register` 提供 alias 覆盖与部分产品图标替换（`dsh-client-ui-theme/README.md:12,28,44`）。token 清单/light-dark 语义见 README `:62-94`，主题状态与持久化见 `:100-102`。
- 深/浅色切换由 ui-layout presenter 应用到文档（`ui-layout/README.md:51`），插件无需自管。[已确认]
- 插件容器/控件必须继承宿主主题；`<style>` 由 `styles.insert(css)` 注入并随插件卸载移除（`slot-catalog.ts:76`；`ui-plugin.md:13`）。[已确认]

### 6.2 本地化

- `ctx.locale.register(ns, {zh,en,...})` + `ctx.locale.bind(ns)`；**必须同时提供 zh/en 基线**，其余可选；编译期按 namespace 做 key 类型校验；slot 渲染的文案随语言热切换（`dsh-client-locale/README.md:40,86-96`）。
- slot 注册可声明 `locale: '<ns>'`，组件收到框架注入的 `t`（`slots.md:95,120`）。
- 新增语言包：`ctx.locale.addLanguage({id,label,fallback})`（fallback 链须终止于 `en`）（`README.md:46-68`）。
- 官方还提供 `ctx.locale.resolveText()` 解析 `LocalizedText`（插件标题/描述/元数据）（`README.md:42-44`）；bundle 显示元数据走 `locale/*.json` 的 `meta.*`（`host-plugin.md:29-52`）。[已确认]

### 6.3 样式/布局红线

- **iframe 被官方实践明确禁止**（原文）：`Do not serve an HTML page from the Host and embed it in an iframe: an iframe document does not receive the host's theme tokens, light/dark switching, or ctx.locale.`（`practices.md:33`）。
- 不得替换 app root、不得向 `document.body` 追加第二个应用（`ui-plugin.md:13`；`practices.md:36`）。
- 不得读取其他插件的 DOM/样式/组件源码来猜布局（`ui-plugin.md:13`）；不得 `require` Harness Client 包（`practices.md:35`）。
- 组件可复制 UI 原语的 markup/CSS/行为（保留 modal focus、Escape、`role="switch"`+`aria-checked`、tooltip 位置等交互细节），但类名要加插件前缀（`practices.md:35`）。
- 视觉验证要求：浅色/深色下与同类宿主页并排检查、控制台无 `slot entry crashed`（`verification.md:5`）。[已确认]

## 7. Q6 Desktop 与 Web 客户端差异

### 7.1 结论：Desktop 复用同一套 Web Client 代码，运行在 Electron renderer

- `dsh-web-frontend` 是 Vite 构建的 Web 应用入口（`dsh-web-frontend/package.json:2-3`）；`src/main.ts:5-37` 显示：
  - 检测 `globalThis.dshDesktopBoot`；Desktop 下等待 `desktop.ready()` 拿到 `injections` 与 `streamBaseUrl`；
  - 设置 `__DSH_TRANSPORT__ = { ownsHost: true, streamBaseUrl }`；
  - 由 Desktop preload 注入 index rows（`applyIndexInjections`），再启动同一个 `AppWebEntry`。
- Desktop Host 是私有 Node 模式进程，依赖包含 `dsh-host-webserver`、`dsh-client-connection`、`dsh-plugin-manager`（`dsh-desktop-host/package.json:2-3,13-26`）。
- client-modules 支持两种 carrier：Web carrier（HTTP `/plugins`）与 shell-owned carrier（`fetchBundle()` 返回同样响应）（`dsh-client-modules/README.md:12`）；Desktop 走后者，且 Desktop forwarder 会把 `/plugins/` 的 cache header 改写为 `no-store`（`README.md:150`）。
- 公开 master `docs/architecture.zh.md` 亦写明：`Electron 使用 Electron Node 模式启动私有 Desktop Host … 窗口立即加载打包 Web 资源，等待启动注入后在同一文档中激活客户端插件。Web 负责 RPC 与流；桌面载体将本地页面连接到已认证的 Host。`

**对插件作者的含义** [已确认]：Client 插件代码、`dsh.client.platform='web'`、slot API、`/plugins` 资源语义在 Desktop 与 Web **相同**；差异集中在 (a) bundle 传输/缓存、(b) 窗口 chrome、(c) 宿主侧能力（文件选择器、打开外部应用等）。

### 7.2 桌面专属契约（客户端插件要注意）

- `html[data-platform='darwin']` **仅由 desktop preload 设置**；ui-layout/ui-sidebar 在 macOS 下使用 `shell.leading` 窗口 chrome 座位、隐藏侧栏列、发布 `--dsh-frame-*` clearance（`ui-layout/README.md:43`；`ui-sidebar/README.md:58`）。
- Windows Electron：`data-windows-titlebar` 标记保留标题栏高度、去掉折叠 rail、发布 `--dsh-windows-content-radius/-sidebar-width`（`ui-layout/README.md:45`）。
- **rc.2 变更**：macOS 下自定义 Client overlay 覆盖可拖拽 header 时，必须显式声明窗口区域（`data-window-drag-exclude` / `data-window-drag-controls`），否则可能无法拖窗（`docs/upgrade-guide/v0.2.2-rc.1/window-drag-regions/guide.md:12-19`）。这是 Desktop 特有、且刚发生的破坏性变更。[已确认]
- Desktop 专属插件（如 product analytics）通过 `!!js ctx.get('profileContext')?.name !== 'desktop'` 条件启用（`dsh-web-app/cordis.patch.yml:37-54`）——说明同一 bundle 可按 profile 分叉行为，Mammoth 若要 Desktop 特化可复用该模式。[已确认]

### 7.3 桌面文件选择器 / 本地路径

- 目录选择是一个 **seam**：Host 侧 `dsh-host-directory-picker-auto` 在启动时解析环境并挂载 native 或 browse 后端（`dsh-web-app/cordis.patch.yml:106-110`）；客户端 `dsh-client-ui-directory-picker-native` 是 renderless occupant，**本地 Electron 下用窄 preload 目录选择桥**，普通 Web 走 Host chooser，远程/进程内部署用 browse 变体（`dsh-client-ui-directory-picker-native/README.md:12,28-36,80-82`）。
- 两个目录流只在当前 Peer 可调用 `directoryPicker/pick` 时注册；owner 始终可用（`README.md:36`）。
- 文件能力：`dsh-client-ui-file-actions` 提供“原文件保存 + 图片剪贴板动作（Web 与 Desktop）”（`packages.md:83`）；打开外部应用由 `dsh-host-open-in-app` + `dsh-client-ui-open-in-app` 对（`packages.md:291`，`dsh-web-app/cordis.patch.yml:70-85`）。
- **插件不能直接读本地文件系统**：renderer 无 Node 能力，数据经 Client model / `workspaceFiles` Remote / `ctx.resources` 的 provider 体系获取（`web-client.md:11-18,28-34`；`client-resources.md`（公开文档）"消费方自己经 Workspace Files Remote 命名空间读取内容"）。[已确认-文档]
- 因此 Mammoth 若要“桌面文件选择 + 导入”，应优先复用 directory-picker seam 与 workspace files Remote，而不是自建 IPC/文件系统访问。[需实测]（需在 Desktop profile 下实装一个最小插件验证）

## 8. Q7 上游升级影响（Client API 稳定性）

### 8.1 版本与发布形态

- 当前是 **rc** 版本：`0.2.2-rc.2`（`dsh/package.json:4`）；安装包内 `experimental` 组明确“pre-stable”（`packages.md:5`）。

### 8.3 稳定性机制与边界

- **Slot 契约是编译期生成的**：catalog 由 `scripts/gen-client-catalog.ts` 从 `SlotMap` 声明与 `slots.register()` 调用点生成，并由 `verify-client-catalog` 在 doc-sync 中做新鲜度校验（`slot-catalog.ts:1-14`；`slots.md:221`）。→ 每个版本都可能重新生成，**没有“slot key 冻结”承诺**。
- **upgrade-guide 是唯一官方 break 通告渠道**（`references/upgrading.md:3`：“DSH upgrade guides describe breaks in DSH surfaces: … Client slots, and persisted data.”）。
- **`engines.dsh` 只是闸门**（§5.4），管理“能否装/能否启动”，不管“API 语义是否变化”。
- **Host release identity 一致才应用新模块图**：页面只在 Host 与页面 boot release 一致时应用 graph；Host 换版本后需 reload（`dsh-client-modules/README.md:51`）。升级 DSH 后插件 bundle 需要重建/重新验证，不能假设旧 bundle 自动可用。[已确认]
- 客户端 bundle 的模块身份（React/Cordis/ui-slots/ui-primitives 单实例）由 shell 静态表保证（`dsh-client-ui-renderer/README.md:58`）；第三方不能用自有 React，否则无法在同一 slot 渲染。[已确认]

### 8.4 对 Mammoth 的升级策略含义

1. Client 侧代码应按“**可重建、可回归**”设计：把 slot key/owner props 使用面收敛到少数适配层；升级时对照 upgrade-guide + 用新 catalog 做静态比对。
2. 不要把业务能力绑在 shipped slot 的“替换”（`replaceRisk: shadows-shipped-ui`）上；优先使用 additive list/keyed 新 id。
3. 订阅 DSH 版本节奏：rc 期间每个 minor/rc 都可能带 break；建议 Mammoth 对 DSH 版本做“锁定 + 升级窗口 + 插件契约回归测试”。
4. 尽量只依赖**官方文档化**的三类面：`dsh.client` 四字段、`ctx.slots.*`（catalog）、`ctx.uiConversation`/projection/commands 等 seam；避免依赖内部 URL/loader 协议。

## 10. 对 Mammoth 的结论与建议

### 10.1 「Mammoth 能否以 DSH Bundle 形式获得完整业务 UI」

**可以得到的部分**（有官方范例、可直接落地）：
- DSH 工作台内的**顶级导航入口 + 长期业务页面**（`main` + `sidebar.panellist`，plugin-manager 同款）：需求/方案/知识/交付各一个 key 即可。
- 会话内**业务视图 tab**（`conversation.view`，trajectory 同款）与**Chat 行/工具卡片**（需求卡、方案卡、交付卡）。
- 右侧面板（文档/知识预览、详情检查器）、底部状态条、overlay/toast。
- 设置页中的 Mammoth 配置分区。
- 主题、语言、隐藏策略与宿主一致（不用 iframe，不导组件库，自建控件）。

**不能得到的部分**：
- **独立应用壳/应用级路由**：不能替换 root、不能挂第二个应用、无官方 router；`main` 只有一个 keyed cell，页面内部导航需自建；页面选择状态在 reload 后重置。
- **完整自由的前端技术栈**：只能 lazy-CJS factory + `require('react')` + 原生 DOM/自写 CSS；不能 import Harness UI 库、不能依赖任意 npm 运行时模块（除非写进 `dsh.client.external` 且提供者存在）。
- **数据通道的完全自由**：第三方新增 Typert Remote namespace 的路径不完整（生成器不在运行时）；必须围绕官方 seam 组织（commands/tools/projections/resources/既有 remote）。[需实测确认最可行组合]
- **产品化分发**：不能成为安装版 optional bundle；需用户/企业以 profile 外部 bundle 方式安装，承担 pnpm 依赖/构建/版本约束。

### 10.2 最大风险（按严重度排序）

1. **Client Slot/API 契约的 rc 期变动风险（最高）**：slot key/owner props/导出类型在 0.2.1→0.2.2-rc.2 内已有多次破坏性变更（§8.2），官方无 LTS 承诺；`engines.dsh` 只挡版本不挡 API。→ Mammoth 需要“适配层 + 契约回归 + 锁定版本窗口”，并预留每次 DSH 升级的重建成本。
2. **业务数据通道风险**：UI 需要读 Mammoth 领域数据，但第三方 Remote/Typert 路径不完整；若必须自建 Host↔Client 通道，可能依赖内部机制（Typert 生成器、webserver 路由、事件 allowlist），升级时更容易 break。→ 优先用 session projections `wire.view` + `ctx.commands` + 工具结果；把“自定义 Remote”作为独立 Spike。
3. **UI 能力落差风险**：没有应用级路由/多页面壳、不能导入组件库，所有控件与样式需自建并跟随主题；这会把“业务 UI”做成 DSH 壳内的工作台页面，而不是独立产品界面。若 Mammoth 产品定位需要独立桌面应用体验（自定导航/多窗口/富交互），Bundle 形态会成为长期限制。
4. **供应链与运维风险**：外部 bundle 安装执行 Host 进程内代码，pnpm 构建脚本可能需审批；Desktop 的包操作由 Desktop 壳拥有（`plugin-manager/README.md:182`）。→ 私有分发需签名/审核与回滚预案。
5. **性能/启动风险**：Client 插件随完整 roster settle 后才首帧；大 UI 插件会影响启动（`renderer/README.md:94-95`）。→ 需测量并控制插件数量/体积。

### 10.3 建议的架构形态（供决策，不是实现）

- **推荐**：Mammoth = 一个外部 bundle（Host 插件 + Client UI 插件 + 可选 preset/MCP），UI 作为“DSH 工作台内的 Mammoth 业务工作台”：
  - 左栏 `sidebar.panellist` 入口 ×N（需求/方案/知识/交付）；
  - `main` 业务页面（每页一个 key）；
  - 会话内：`conversation.view`（Mammoth 会话视图）+ Chat 行/toolview 卡片；
  - 右栏：文档/知识预览面板；
  - 设置页：Mammoth 配置；
  - 领域数据：Host 服务 + session projection `wire.view` + `ctx.commands` + 工具结果。
- **保留退路**：若产品要求独立应用体验或多窗口，则采用“DSH 扩展（Agent 能力/工具/卡片）+ 独立 Mammoth 前端（自建壳、通过 Host API/Remote 或独立 Domain API 通信）”的混合形态；Bundle 只承载 Agent 侧能力与轻量工作台入口。
- **必须的 Spike**（按优先级）：
  1. 4 合 1 bundle 组装 + 安装 + 页面/导航/卡片全链路最小验证（含 Theme/Locale 一致性）。
  2. 第三方 Host 服务 → Client UI 数据通道可行性（projection `wire.view` / commands / 自定义 Remote 三条路线对比）。
  3. `main` 页面内多级路由与状态保持（reload/切换 Session 的行为）。
  4. Desktop profile 下目录选择器 + workspace 文件读取。
  5. 一次 DSH 小版本升级的回归演练（catalog diff + upgrade-guide 清单）。
