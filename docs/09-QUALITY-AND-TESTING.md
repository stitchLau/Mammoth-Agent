# 09 — 工程质量与测试策略

## 1. Definition of Done

任何功能只有同时满足以下条件才算完成：

- 对应规格和验收标准明确；
- 代码实现符合当前架构边界；
- 相关单元/集成/端到端测试通过；
- lint、typecheck、build 等项目检查通过；
- 错误、空状态、加载状态和边界条件有处理；
- 权限与审计按风险要求实现；
- 数据迁移可重复、可验证，必要时可回滚；
- 用户可见文档和 Agent 指令已更新；
- 完整 diff 已人工/Agent review；
- 未完成事项和已知风险已明确记录。

## 2. 测试分层

- Unit：领域规则、状态机、权限判断、解析和映射。
- Integration：数据库、存储、检索、Git、Runtime Adapter。
- Contract：Agent Tool Schema、Domain API、外部集成接口。
- E2E：项目创建、资料导入、检索、需求收集、方案审核、结项。
- Security：跨项目检索隔离、未授权文件访问、Prompt Injection、工具审批。
- Regression：固定样例项目和需求案例的输出结构/关键事实回归。

## 3. AI 输出评测

不要仅用“文档看起来不错”验收。建立可复用测试样例：
- 项目事实问答与引用准确性；
- 代码定位准确性；
- 数据库对象检索准确性；
- 需求缺口识别召回情况；
- 冲突识别；
- 业务闭环完整性；
- 技术方案事实一致性；
- 方案到任务的追溯完整性；
- 错误拒答和未知标记能力。

AI 测试应允许合理表述差异，但关键事实和引用必须可验证。

## 4. UI 验收

不仅检查截图。验证真实交互、键盘操作、窄屏布局、加载/空/错误状态、权限不可见与不可访问、长文本和附件展示。

## 5. 代码审查

审查者重点问：是否符合需求？有没有扩大范围？是否引入重复抽象？错误处理是否真实？是否有未授权访问？数据是否能恢复？Agent 是否能越权？测试是否真的覆盖风险？

## 6. 发布前检查

运行格式化、lint、typecheck、测试、构建、依赖漏洞/许可证审查、迁移演练、备份恢复演练、发布说明、回滚方案和配置检查。
