# M4.5 落地计划：生产集成与运营启用

- **状态**：Draft（2026-11-13，负责人确认“需要 M4.5 落地计划”）；**M4 已完成本机验收，M4.5 待负责人提供轮换后的 Jira 只读令牌/SMTP/企微/CSM 导出资料后启动**
- **日期**：2026-11-13
- **定位**：M4-core（本地/只读/配置后启用）与 M5（平台规模化）之间的桥接阶段
- **依据**：`docs/04-MVP-STRATEGY.md` Phase 4、`docs/12-ROADMAP.md` M4、`decisions/ADR-0011`、`ADR-0012`、`ADR-0013`、`docs/specs/M4-PHASE4-PLAN.md`
- **原则**：仍不接触生产客户数据/生产凭据；外部调用必须白名单、只读、可审计、可回滚；**PostgreSQL 多实例不在 M4.5，归 M5**。

## 1. 为什么需要 M4.5

M4-core 交付的是“本地可验证”的能力：只读文件导入、Jira 导出文件映射、站内通知、邮件/企微完整实现但默认关闭、Agent 只读交接。真正接入负责人环境还需要：

- Jira 只读 API（负责人已给地址 `http://119.145.133.146:18009/`）；
- CSM 端点/产品确认后的适配器；
- SMTP/企微渠道的实际配置、测试发送、监控与运营；
- 可选：远程 Agent 网关、团队服务器试点；
- CI 远端与真实脱敏项目验收。

这些工作依赖外部账号、网络、配置或负责人授权，不能在 M4-core 中假设完成，因此单列 M4.5。

## 3. 切片详情

### M4.5-1 Jira 只读 API 连接器

**目标**：在负责人环境只读拉取 Jira issue，进入现有导入/证据候选流程。

**前置**：

- M4 S3/S4 完成（导入框架、Jira 字段映射、证据候选）；
- ADR-0011 生效；
- 确认 Jira 产品/版本（Cloud vs Data Center）与官方 API 版本；**以官方文档为准**（Cloud 参考 [Jira Cloud REST API v3](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-search/)；Data Center 需按对应版本文档）；
- 负责人提供**只读**账号/令牌（或确认匿名只读不可用）；账号权限最小化；不提供管理员账号；
- 网络：目标 `http://119.145.133.146:18009/` 当前为 HTTP。**负责人 2026-11-13 已明确接受 HTTP**；M4.5-1 仍必须使用只读账号、仅受控内网/网络隔离、记录风险接受，并不把凭据写入仓库/日志；若后续可提供 HTTPS，优先切换。
- 白名单：仅该主机/端口；禁止重定向到其他主机；超时/响应大小上限。

**实现要点**：

- `JiraReadOnlyAdapter implements ExternalAdapter`：JQL 搜索、字段读取、分页（startAt/maxResults 或官方对应参数）、增量（updated >= lastSync）、限速/退避；
- 认证：`SecretProvider` 注入（环境/OS 存储）；不写 DB/日志；错误脱敏；
- 映射：复用 S4 字段映射；`external_record` 存 key/version/hash/URL；证据候选；人工映射；
- 同步状态：`external_source.last_sync_at`/游标（V11 迁移，若需要）；批次/错误可见；
- 审计：`integration.jira.read`（查询条件脱敏/结果数/耗时/错误），不记录 issue 正文；
- 不做：创建/更新/评论/状态流转/附件下载（附件只留 URL）。

**退出标准**：

- 本地 mock Jira（JDK HttpServer/WireMock）契约测试通过（分页/增量/限速/错误/脱敏）；
- 负责人批准的只读 smoke test 成功拉取指定项目/少量 issue；
- 无写请求（网络/日志/审计断言）；
- 失败可重试/死信；不阻塞主流程；
- 文档：`docs/dev-setup.md` 配置、`docs/evidence/M4.5-VERIFICATION.md`。

**风险**：Jira 版本/字段差异、HTTP 凭据风险、限速、网络不通、只读账号权限不足。

### M4.5-2 CSM 适配器

**前置**：负责人提供 CSM 产品名、接入端点、API 文档、认证方式、只读账号；在此之前**不实现、不猜测**。

**实现要点**：

- 复用 `ExternalAdapter`/`ImportMappingProfile`/`external_*` 表；
- `CsmReadOnlyAdapter`（具体端点/字段待定）+ 契约夹具；
- 若 CSM 只支持文件导出，则按 S3 通用导入处理，不强行 API；
- 审计/权限/幂等/失败补偿与 Jira 一致。

**退出标准**：端点确认；契约测试；负责人批准的只读 smoke test；文档与配置说明。

**若端点长期不提供**：保持 SPI/规划，不进入实现；在 backlog 保留。

### M4.5-3 通知渠道生产启用

**前置**：M4 S5 完成（邮件/企微完整实现、默认关闭）；负责人提供 SMTP/企微配置。

**步骤**：

1. 配置 SMTP：host/port/from/username/password/STARTTLS；密码走环境/OS 存储；
2. 配置企微机器人：webhook URL（凭据）、消息类型、事件白名单、限速；
3. 启动校验：缺失参数时报错；UI 显示 enabled/configured；
4. 测试发送：`POST /api/admin/notifications/channels/{channel}/test` 到测试目标；审计；
5. 观察：投递状态、失败/死信、限速；提供运维手册；
6. 启用范围：先内部测试群/负责人邮箱，再逐步扩大；**不向客户发送**。

**退出标准**：测试邮件/企微消息到达指定测试目标；失败可重试/死信；审计/脱敏；默认关闭时零外发回归通过；负责人确认启用。

### M4.5-4 远程 Agent 网关（可选）

**触发**：外部 Agent 不能在本机运行、必须远程只读访问 Mammoth 时。

**方案**：

- 只读 HTTP API（知识检索/需求上下文/交接包元数据）或 MCP over HTTP（视 DSH/Agent 能力）；
- 服务令牌（opaque token，DB 哈希、可撤销、最小权限 viewer）；
- TLS（反向代理）、限速、审计 `agent.tool_call`（DB 写入由 writer 完成）；
- 不提供写路径；不暴露项目外数据；令牌轮换/撤销。

**替代**：继续使用 BG-01 交接包 zip + 本地 MCP；多数外部 Coding Agent 场景足够。

**退出标准**：令牌认证/撤销、只读工具、审计、限速、跨项目隔离；安全评审。

### M4.5-5 团队服务器试点（可选）

**触发**：负责人要求内网团队共享，而非本机/单用户。

**范围**：

- 单节点、SQLite；反向代理 TLS；`forward-headers`；Secure Cookie；默认绑定 localhost；
- 备份/恢复演练；监控/日志；OS 服务化（可选）；
- BG-02：基线/交付记录部署版本、schema 版本/DDL hash；
- **不做 PG/多实例**（M5）。

**退出标准**：内网试点验收；TLS/Cookie/代理头；备份恢复；无网络盘数据根；负责人确认。

### M4.5-6 CI 远端与真实项目验收

- 推送后确认 GitHub Actions 三个 job 实际通过（后端/前端/E2E）；失败修复；
- 真实脱敏项目验收：负责人提供授权项目/脱敏数据；走 M3 验收演练 + M4 导入/通知/Agent 流程；
- 证据：`docs/evidence/M4.5-VERIFICATION.md`、`docs/M4.5-ACCEPTANCE.md`；
- 仍禁止生产凭据/生产数据。

## 4. 顺序与依赖

```text
M4 S1–S5 完成
  ├─ M4.5-1 Jira 只读 API（需 S3/S4 + ADR-0011 + 账号/网络确认）
  ├─ M4.5-2 CSM（需端点/产品）
  ├─ M4.5-3 通知启用（需 S5 + SMTP/企微配置）
  ├─ M4.5-4 远程 Agent 网关（可选，需 S2/S5 + 安全评审）
  └─ M4.5-5 团队服务器试点（可选，需 S6 + 部署环境）
       └─ M4.5-6 CI/真实验收（跨切片）
```

建议顺序：**M4.5-3（通知启用）→ M4.5-1（Jira 只读）→ M4.5-6（CI/验收）→ M4.5-2（CSM）→ M4.5-4/5（按需）**。理由：通知启用风险最低、能立即改善协作；Jira 只读价值最高但依赖账号/网络；CSM 端点未定；远程网关/团队服务器按需。

## 6. PostgreSQL 多实例：明确放到 M5

### 6.1 结论

**PostgreSQL + 多实例 + HA 在 M5 完成，不在 M4/M4.5。** M4/M4.5 保持单节点、单写者、SQLite(WAL)。M5 的完整切片、迁移/切换、备份/回滚与验收见 [`M5-PHASE5-PLAN.md`](M5-PHASE5-PLAN.md)。

### 6.2 触发条件（满足任一即启动 M5 评估）

- 需要 2 个以上应用实例/滚动升级/HA；
- 单节点写入或任务队列成为瓶颈；
- 数据量/备份窗口/报表需求超出 SQLite 可接受范围；
- 需要跨机共享同一权威库或只读副本；
- 内网团队规模/并发超过单节点容量假设（需实测）。

### 6.3 M5 前置

1. 更新 ADR-0003（PG 版本/驱动/连接池/迁移策略）；
2. `db/migration-pg` 与 SQLite/PG 双跑迁移测试；
3. Hibernate 方言/实体映射校验；避免 SQLite 专有 SQL；
4. 任务领取 `SELECT ... FOR UPDATE SKIP LOCKED`（或等效）；幂等/死信；
5. 登录限速/验证码/会话共享存储（替代进程内 `LoginRateLimiter`）；
6. `pg_dump/pg_restore` 备份恢复演练；监控/告警；
7. TLS/部署/回滚手册；多实例健康检查；
8. 数据迁移工具：从 SQLite 导出/导入到 PG（复用/扩展现有导出格式）。

### 6.4 不在 M5 之前做的事

- 不把 SQLite 数据根放网络盘/云同步盘（ADR-0008 拒绝）；
- 不用多进程写同一 SQLite（实例锁阻止）；
- 不假设共享会话=多实例（登录限速仍是进程内）；
- 不在未演练前切换权威库。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Jira HTTP 凭据泄露 | 未 HTTPS 不发送凭据；风险接受需书面；内网隔离；只读账号 |
| Jira API 版本差异 | 官方文档 + mock 契约 + 小范围 smoke test |
| CSM 长期无端点 | 保持 SPI/backlog；用文件导入兜底 |
| 邮件/企微误发 | 默认关闭 + 配置校验 + 测试目标 + 限速 + 审计 |
| 远程网关扩大攻击面 | 只读 + 令牌 + TLS + 限速 + 跨项目测试；否则继续离线 zip |
| 团队服务器运维不足 | 单节点/最小配置/备份演练；PG 推迟到 M5 |
| 真实项目验收不可得 | 保持合成/脱敏演练，明确限制，不假装完成 |
