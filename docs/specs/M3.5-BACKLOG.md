# M3.5 技术债与延期清单

- **日期**：2026-11-13
- **来源**：M3 阶段复盘（用户确认将未闭环项登记为 M3.5/技术债）
- **规则**：延期不等于删除；每项必须写明价值、延期原因、依赖、恢复条件和验收口径。

## BG-01 交接包作为可携带文件导出

| 项 | 内容 |
|---|---|
| 用户价值 | 把 Approved Design/任务/验收/基线打成可交给外部 Coding Agent 或客户评审的文件包，避免人工复制 Markdown |
| 当前状态 | `GET /api/projects/{p}/work-items/{w}/handoff` 只返回 Markdown JSON；未落 Artifact、无下载 |
| 延期原因 | M3 退出条件可用 API 响应满足；文件导出需要额外的包格式/清单/脱敏规则评审 |
| 依赖 | ADR-0007（基线/只读）、ADR-0004（Artifact 存储）；导出格式与不含凭据的约束 |
| 恢复条件 | M4 前或客户首次要求"给外部 Agent 一份包"时 |
| 验收 | 生成 zip（manifest + 业务/技术方案 + 任务 + 验收 + 基线 commit），可下载、可校验 sha256、不含凭据；审计 `handoff.export` |
| 参考 | `docs/07-WORK-ITEM-LIFECYCLE.md` §7 |

## BG-02 ProjectBaseline 增加部署版本与 DB 结构版本

| 项 | 内容 |
|---|---|
| 用户价值 | 让"项目基线"不仅回答"哪个 commit"，也回答"部署了哪个版本、库结构是哪个版本" |
| 当前状态 | `project_repository`/`project_baseline_repo` 只存 commit/branch/dirty/worktree |
| 延期原因 | 部署版本/DDL 版本没有统一来源（客户环境/发布系统），需要接入或人工登记流程 |
| 依赖 | ADR-0007 §4/§5、项目基线的运维登记流程 |
| 恢复条件 | 有真实项目需要"版本+DDL"级基线，或 M4 接入发布系统时 |
| 验收 | 基线可记录 deployment_version、schema_version/DDL hash；方案/交付快照可引用；导入导出保留 |
| 参考 | `docs/03-DOMAIN-MODEL.md` §1/§2 |

## BG-03 验收矩阵连接业务目标与实施证据；偏差目标 UI

| 项 | 内容 |
|---|---|
| 用户价值 | 从"验收标准覆盖"升级为"业务目标 → 设计项 → 任务 → 验收 → 变更/证据"的完整可追溯矩阵 |
| 当前状态 | `MatrixRow` 含验收标准、设计项标题、任务完成数；没有业务目标列、没有每行 execution/change 链接；偏差 UI 的 targetType/targetId 传 null |
| 延期原因 | M3 先保证任务完成度可计算；业务目标映射与证据链接需要额外的查询/聚合模型与 UI |
| 依赖 | `SolutionConsistency.traceability`、`execution_change`、`execution_deviation` |
| 恢复条件 | 客户评审要求逐条验收给出证据时 |
| 验收 | 矩阵每行含根业务目标、关联任务、关联执行记录/变更；偏差可关联设计项/任务/验收标准并在 UI 展示 |
