# ADR-0011: 外部系统集成与凭据边界（只读优先）

- 状态：**Accepted v1.0（2026-11-13，M4 S3/S4 文件导入范围）**；真实 Jira 只读 API、CSM 适配仍按 M4.5 计划验证，启用前不改变“外部系统权威”边界
- 日期：2026-11-13
- 决策人：项目负责人（方向确认）；Lead Agent 起草
- 相关需求/功能：M4 企业集成（Jira/CSM）、M4.5 生产集成、M5 双向同步
- 相关文档：`docs/04-MVP-STRATEGY.md` Phase 4、`docs/12-ROADMAP.md` M4、`docs/02-PRODUCT-BOUNDARIES.md` §1、`docs/03-DOMAIN-MODEL.md`、`docs/07-WORK-ITEM-LIFECYCLE.md` §3、`docs/08-SECURITY-AND-TRUST.md` §5、`decisions/ADR-0007`（只读 Git）、`decisions/ADR-0008`（单写者/导出导入）、`decisions/ADR-0006`（身份授权）

## 背景与约束

- `docs/04-MVP-STRATEGY.md` Phase 4 明确列出 Jira/CSM、MCP、企业微信/邮件、外部 Agent 适配；`docs/12-ROADMAP.md` M4 只给范围，没有给“集成形态/凭据/数据边界”的决策。
- 现状代码（2026-11-13 核对）：`services/domain` **没有**任何 Jira/CSM 客户端、出站 HTTP 客户端、邮件依赖或调度器；`McpToolService` 只有 3 个只读工具；`system_type`/外部来源/导入批次等模型不存在。
- 负责人 2026-11-13 提供 Jira 访问地址 `http://119.145.133.146:18009/`；CSM 暂未提供接入端点；企微先以机器人接入；SMTP 采用“完整实现、配置后启用”。服务器与证书暂不处理（内网/本机开发环境）。
- 安全边界（`AGENTS.md`、`docs/08`）：不接触真实客户生产数据/生产凭据/生产环境；外部系统调用与发送必须先设计边界并经负责人批准；凭据不得写入提示词、参数、日志、截图或仓库。
- 产品边界（`docs/02` §1）：外部业务系统继续管理其权威交易；Mammoth 可以导入/引用，但不得把外部记录私自复制后当作权威数据。

## 需要解决的问题

1. 集成形态：只读文件导入、只读 API、双向同步的推进顺序；
2. 先做 Jira 还是 CSM；
3. 凭据如何保存、注入、轮换与脱敏；
4. 允许出网的范围与传输安全；
5. 导入数据的权威性、幂等、版本与失败补偿；
6. 外部记录如何映射到 WorkItem/RequirementEvidence，且不污染业务权威状态；
7. 审计、回滚与未来双向同步的演进路径。

## 备选方案

- **方案 A（推荐）**：只读文件导入（CSV/JSON + 映射）→ 只读 API（带凭据、白名单）→ 双向同步（独立里程碑）。M4 只做文件导入；M4.5 做只读 API；双向同步不在 M4/M4.5。
- **方案 B**：先直连 Jira/CSM 只读 API。能力强，但立即引入凭据、网络、代理、证书、版本差异与生产环境风险；当前无官方 API 版本确认与测试账号，不可先行。
- **方案 C**：双向同步优先。需要冲突模型、写回权限、失败补偿与外部系统变更语义；风险最高，明确拒绝作为首版。
- **方案 D**：不做集成，仅人工粘贴。无法满足 M4 的集成目标，且已确认要保留产品边界，不采用。

## 决策

采纳 **方案 A**，并明确以下 12 条：

1. **只读优先**：M4 只实现**文件导入**（CSV/JSON + 映射配置）；M4.5 才实现 Jira/CSM 的**只读 API**；双向同步放 M5 之后并另立 ADR。M4/M4.5 不执行任何外部写操作（创建/更新/删除/评论/状态流转）。
2. **外部记录是证据/候选，不是权威工作项**：导入产生 `external_record` 与“证据候选”；必须由人显式映射到已有 WorkItem 或确认创建，才进入 `requirement_evidence`。不得自动改变需求状态、就绪结论、方案或知识状态。
3. **Jira 先于 CSM**：Jira 有官方 REST API 文档与稳定导出格式；CSM 目前只有 Phase 4 名称，没有产品/API 定义，不能猜测实现。CSM 只保留 `ExternalAdapter` SPI、契约与映射骨架，等负责人提供端点/产品后进入 M4.5。
4. **适配器 SPI**：`ExternalAdapter`（解析/校验/映射）、`ImportMappingProfile`（列/字段映射）、`ExternalSource`（来源元数据）、`ImportBatch`（批次/校验/应用）、`ExternalRecord`（外部记录/版本/哈希）。业务服务只依赖接口，不直接依赖 Jira/CSM SDK。
5. **凭据管理**：只允许环境变量或 OS 凭据存储（`SecretProvider` 抽象）；**禁止**写入数据库、仓库、导出包、交接包、日志、提示词、截图。使用**只读服务账号**，最小权限；定期轮换；凭据缺失时集成保持禁用并给出可操作错误，不得回退到匿名/共享账号。
6. **出网边界**：按集成配置主机白名单；只允许 HTTPS（带凭据的请求）；禁止任意 URL、重定向到非白名单主机、代理自动发现；超时/重试/响应大小上限；错误信息脱敏。**负责人提供的 Jira 地址当前是 HTTP**：在未启用 HTTPS 或未做“受控内网 + 明确风险接受”前，M4/M4.5 不得向其发送任何凭据；M4 不调用该地址。
7. **数据边界**：外部导入内容按 Confidential 处理；原始文件存 Artifact（内容寻址 + sha256），记录只存必要结构化字段与来源定位；不自动进入 RAG/知识库；不把外部附件二进制写入数据库正文；不把生产凭据/连接串带入项目数据。
8. **幂等与版本**：以 `(source_id, external_type, external_id, external_version)` 唯一；同一文件/记录重复导入不产生重复；外部版本变化产生新记录/新证据批次，不覆盖旧证据；批次以原始文件 sha256 + 映射 profile 识别重复。
9. **失败补偿**：批次状态（上传/校验/应用/失败）+ 行级错误 + 重试/退避/死信；应用阶段单事务或可恢复的分段事务；失败不静默丢弃；审计 `integration.import`、`integration.import.dry_run`、`external_record.map`、`external_record.reject`。
10. **dry-run 默认**：上传先校验并返回报告（行数/接受/拒绝/重复/错误行号），人确认后才“应用”；dry-run 不写业务表、不产生证据、不触发通知。
11. **M4.5 只读 API 门禁**：必须先确认 Jira 产品/版本（Cloud vs Data Center）、官方 API 版本、认证方式、网络可达性与 TLS；通过 ADR-0011 附录/实施记录批准后才可写连接器；连接器只允许 JQL 搜索/读取字段/分页/增量拉取，不写、不评论、不转状态。
12. **CSM 记录为待办**：在 `docs/specs/M4.5-PHASE45-PLAN.md` 中保留 CSM 接入切片、依赖、验收与恢复条件；未提供端点前不实现、不猜测 API。

## 决策理由

- 文件导入没有凭据/网络/生产账号面，能在本机用合成数据完整验证“来源、幂等、版本、映射、审计、失败补偿”，与 `AGENTS.md` 的“外部集成默认先做只读导入/本地演示”一致。
- 外部记录不进入权威工作项，避免把 Jira/CSM 的记录复制成 Mammoth 的“事实”，符合 `docs/02` 的边界与 `docs/06` 的防污染原则。
- 先 Jira 后 CSM 是因为 Jira 的 API/导出格式可查、可测；CSM 缺产品/API 定义，先做会变成臆造。
- 凭据只走环境/OS 存储、只读账号、HTTPS 优先/受控内网白名单，能把“集成”从“把生产密码放进 SQLite”这种不可接受形态中隔离出去。负责人 2026-11-13 明确接受当前 Jira HTTP 地址；M4.5 带凭据调用仍必须仅受控内网 + 网络隔离 + 只读账号，并记录风险接受。
- 幂等/版本/失败补偿/审计是集成的最小非功能底线，不能以“先跑通”为由跳过。

## 取舍和影响

- **正向**：无出网即可完成 M4 集成闭环；可回滚（关闭导入/删除批次即可，不影响既有业务表）；不引入外部写风险；Jira/CSM 适配器可替换。
- **负向**：M4 不能实时同步 Jira；需要人工导出文件/确认映射；CSM 上线时间取决于端点提供；M4.5 才验证真实 API。
- **运维成本**：需要导入操作手册、映射配置说明、失败处理与审计查看；M4.5 需要只读账号与网络白名单。
- **性能**：CSV/JSON 大文件需流式解析与行数/大小上限（建议 50 MB / 50k 行，可配置）；应用阶段分批提交，避免长事务。
- **兼容**：新增表通过 Flyway V9；导出/导入需更新 `AdminTables` 与 `MigrationTest`；旧数据不受影响。

## 安全/数据/迁移影响

- 新增表（M4 S3，V9）：`external_source`、`import_batch`、`external_record`；均为项目级元数据/证据索引，无凭据、无源码正文。
- `external_record` 的 `source_url_sanitized` 可能含内网主机名/路径，按 Confidential 处理；导出/截图需脱敏。
- 原始导入文件作为 Artifact 存储，遵循 ADR-0004 内容寻址；不覆盖、不删除（除非项目管理员按保留策略处理）。
- 凭据不落库；`SecretProvider` 只从环境/OS 读取；日志与错误消息统一脱敏（URL userinfo、token、Authorization、webhook key）。
- 回滚：关闭集成配置 + 停止导入即可；已导入记录保留（审计需要），不自动删除；删除项目数据走既有管理流程。

## 验证计划和结果

**S0（本 ADR）**：代码/文档证据核对完成；Jira 目标地址记录；CSM/企微/SMTP 形态记录；无外部调用。

**M4 实现时必须补齐的验证**：

1. CSV/JSON 解析：引号、逗号、换行、BOM、中文、空值、超长字段、坏行行号；
2. 幂等：同文件重复上传/应用不重复；外部版本变化生成新记录；
3. preview 零业务写入；应用阶段失败可回滚/可恢复；
4. 跨项目导入/映射 403；viewer 不能导入；
5. 原始文件 sha256/大小与 Artifact 一致；证据 locator 可回溯；
6. 审计 `integration.import.preview`/`integration.import`/`map` 落库且不含敏感正文；
7. 无出网：测试期间用网络探针/依赖注入断言没有外部 HTTP 调用；
8. 导出/导入包含新表并通过 `admin-drill`。

**M4.5 必须补齐**：Jira 只读 API 的官方文档核对、只读账号、TLS/白名单、分页/增量、限速/错误、真实只读 smoke test（经负责人批准）。

## 回滚或替代路径

- 若文件导入在真实 Jira 导出格式上不可用 → 保留 SPI，改为“人工整理 CSV/JSON 模板”，仍不直连生产。
- 若客户禁止任何外部连接 → 永久使用文件导入/交接包，不启用 M4.5 API。
- 若未来必须双向同步 → 新 ADR：冲突模型、写回权限、外部状态机、幂等键、补偿与审计；不得在现有只读适配器上偷偷加写操作。
